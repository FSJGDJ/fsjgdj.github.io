## 0. 先说清楚：参考站其实没有"作品展示页"

必须先对齐预期，否则容易照着一个不存在的东西去仿。

参考站 `futurefe414.github.io` 的技术栈是 **Hexo 7.3.0 + Butterfly 主题**（`butterfly-extsrc` 插件包），主色 `#FFB7C5` 粉。它的导航是：首页 / Tags / Categories / List(Music、Movie) / Friends / About——**没有任何相册、画廊、作品集页面**。

它的"图片展示"实际只有三处，我们能借鉴的是这三处的**模式**：

| 层级 | 实现 | 实测数据 |
| --- | --- | --- |
| 全站底层 | 可平铺纹理图 | `#web_bg` 背景图，页头 `#page-header`、页脚 `#footer` 复用同一张图 |
| 列表封面 | 左右交替卡片封面 | `.post_cover` 宽 42%（实测 364×269px），`overflow:hidden`，图片 `transition: filter .375s, transform .6s`，悬停 `transform: scale(1.1)` |
| 正文图片 | FancyBox 灯箱 | JS 自动把正文图片包成 `<a data-fancybox="gallery" data-caption="…">`，配置 `Hash:false / Thumbs.showOnStart:false / Panzoom.maxScale:4 / Carousel.transition:slide` |

响应式：仅一个 `max-width: 768px` 断点——封面变 `width:100%; height:230px`，且 `order:0` 取消左右交替。

**结论**：我们要做的是一个参考站**没有**的新页面，只能借鉴它的图片呈现手法，不能"照抄某个页面"。

## 1. 功能定位与目标用户

### 1.1 三种可选定位（需要你选一个）

| 方案 | 形态 | 适合 | 维护成本 |
| --- | --- | --- | --- |
| **A 作品集** | 精选 10–30 件，每件有标题、说明、技术栈/时间线，多图 | 想展示"做过什么"、对外找机会 | 高（每件要写文案） |
| **B 图片归档** | 全量堆放，按时间/标签筛选 | 纯个人影像留存 | 低（丢进去就行） |
| **C 混合**（推荐） | 默认网格浏览，点开灯箱看大图 + 说明，支持按标签筛选 | 兼顾展示与归档，扩展性最好 | 中 |

### 1.2 目标用户

- **主要**：博客读者——想快速浏览、直观感受你的产出，而不是读技术文章
- **次要**：你自己——需要一个整理与回看的地方
- **不服务**：搜索引擎（可做但不优化），移动端占比预计 <20%，按桌面优先设计

### 1.3 与现有站点的关系

- 导航新增一项（当前：首页 / 目录 / GitHub / 主题按钮）
- 复用现有资产：毛玻璃卡片 `--card`、靛蓝 `--accent`、衬线标题 `--font-serif`、今天新增的动效变量 `--dur-*` / `--ease`、已有的 `.reveal` 进场动画、以及**已写好的 Lightbox**（支持键盘切换、触摸滑动、计数、ESC）
- 不引入任何新 UI 库

## 2. 核心交互与视觉元素拆解

### 2.1 值得借鉴的 4 个模式（附适配调整）

**P1 · 裁切悬停放大**（来自参考站封面）
```css
.cover { overflow: hidden; }        /* 裁切容器 */
.cover img { transition: transform var(--dur-slow) var(--ease); }
.card:hover .cover img { transform: scale(1.06); }
```
- 参考站是 `scale(1.1)` + 0.6s，我们用 1.06 + 0.3s——**更克制**，1.1 在小图上会露出裁切边缘
- 适配点：参考站图片是直角硬边卡片，我们是圆角玻璃卡，需要给 `.cover` 加 `border-radius` 继承

**P2 · 左右交替布局**（来自参考站封面）
- 桌面：封面与文字左右交替，奇偶切换
- 窄屏（<768px）：封面置顶 100% 宽、高 230px，取消交替
- **是否采纳需你定**：交替布局在作品页信息量大时容易节奏杂乱，若作品图多为竖构图，建议改成**统一左图右文的重复单元**（更稳）

**P3 · 灯箱**（来自参考站 FancyBox 配置）
- 关键参数照搬其思路：默认不自动显示缩略图栏、缩放上限 4×、切换用 slide 动画
- 我们的 Lightbox 已具备全部能力，只需扩展"从网格打开时接收图片数组 + 当前索引"，**不引入 FancyBox**

**P4 · 可平铺纹理背景**（来自参考站 `#web_bg`）
- **不建议照搬**：你的站点已有照片背景 + 漂移光斑，叠纹理会打架

### 2.2 排版方式（沿用你现有体系）

| 元素 | 规格 | 依据 |
| --- | --- | --- |
| 区块标题 | 衬线 `--font-serif`，与文章标题同级 | 站点基线风格 |
| 卡片标题 | 衬线，`--text` 色 | 同上 |
| 说明文字 | 无衬线 0.9rem，`--muted`，**2 行截断**（`-webkit-line-clamp:2`） | 参考站摘要也是固定行数 |
| 元信息行 | 日期 `·` 标签，0.78rem `--muted`，沿用你卡片现有 `.post-meta` | 已有样式，直接复用 |
| 圆角 / 阴影 | 14px / `0 8px 32px rgba(0,0,0,.1)` | 与现有卡片完全一致 |

### 2.3 动效（全部对齐今天刚统一的节奏变量）

| 场景 | 效果 | 参数 |
| --- | --- | --- |
| 进场 | 上浮淡入，逐条错开 | `opacity var(--dur-slow)` + `transform .5s`，错开 60ms 封顶 6 条 |
| 悬停 | 封面放大 + 卡片阴影加深 | `transform var(--dur-slow) var(--ease)` |
| 灯箱开合 | 遮罩淡入 + 图片淡入上移 | `var(--dur-base)` |
| 减弱动效 | 全部关闭 | `@media (prefers-reduced-motion: reduce)`（你已有的块，直接扩展） |

### 2.4 响应式断点（与你现有体系一致）

| 断点 | 表现 |
| --- | --- |
| ≥1400px | 3 列网格 + 右侧可粘性筛选栏（延续首页分栏语言） |
| 1024–1399px | 2 列，筛选栏移到网格上方横向条 |
| 640–1023px | 1 列，封面 16:10 固定比例 |
| <640px | 1 列，封面 4:3；**悬停效果不适用**，点击直接开灯箱 |

## 3. 数据来源与内容组织

### 3.1 图片资源：明确不采纳参考站的做法

参考站的封面图来自 **`loliapi.com` 随机动漫图 API**，背景纹理**外链 `i.loli.net`**。三个问题：每次刷新图都变、对方挂了就全挂、有版权风险。

**建议**：全部本地化，存 `src/assets/gallery/`（放 `src/assets` 而非 `public`，才能走 Astro 的构建期图片优化）。

### 3.2 元数据字段（新建 collection `gallery`）

```ts
schema: z.object({
  title: z.string(),            // 作品/图片标题
  desc: z.string().optional(),  // 一句话说明，列表页 2 行截断
  date: z.coerce.date(),        // 创作日期，列表排序与筛选用
  tags: z.array(z.string()).default([]),   // 分类标签
  cover: z.image(),             // 列表用封面（构建期压缩成缩略图）
  images: z.array(z.image()).default([]), // 详情/灯箱用的原图，可多张
  featured: z.boolean().default(false),  // 精选（首页或页首展示）
})
```

### 3.3 两种组织方式

| 方式 | 结构 | 适合 |
| --- | --- | --- |
| **一件作品一个文件** | `src/content/gallery/xxx.md` + frontmatter 里的多图 | A/C 方案，需要为每件写说明 |
| **一张图一个文件** | 每张图一个 md，字段极简 | B 方案，批量导入快 |

推荐前者：你的内容体量（4 篇文章）说明更可能做"作品"而非"随手图"。

### 3.4 ⚠️ 前置问题（阻塞项）

**目前 4 篇文章正文里 0 张图**，`public/images` 只有 `avatar.jpg` 和 `bg.jpg`。所以这个页面的内容来源需要你先回答：

1. 图片从哪来？手机拍摄 / 截图 / 绘图 / 网络素材？
2. 大约多少张？（<20 / 20–60 / 60+）
3. 需不需要给每张写说明，还是只放图 + 标签？

内容没定之前，页面骨架可以先做，但**数据层 schema 建议等你确认字段后再落**。

## 4. 技术选型与实现思路

### 4.1 框架：Astro 静态（沿用，不引入新框架）

- 理由：已是 Astro 7.2.2 + GitHub Pages，构建期全静态，图片优化天然在构建期完成
- 对比方案：纯手写 HTML（不可维护）、引入 React/Vue 画廊组件（为一个页面增加运行时体积，不值）
- 关键：新增 `src/pages/gallery.astro` + `src/content/gallery/`（或 `src/content.config.ts` 里加 collection）+ 导航加一项

### 4.2 图片管线（参考站完全没做，我们必须做对）

用 `astro:assets`（项目已装 `sharp`，可用）：

```astro
---
import { Image } from "astro:assets";
---
<Image src={item.data.cover} alt={item.data.title}
       width={480} height={320} loading="lazy" decoding="async" />
```

收益：构建期自动生成多尺寸 + 现代格式（WebP/AVIF），按实际显示尺寸压缩，**一张 4000px 原图能降到几十 KB**

### 4.3 懒加载与性能策略（逐条对应）

| 措施 | 做法 | 解决什么 |
| --- | --- | --- |
| 原生懒加载 | `loading="lazy" decoding="async"` | 首屏只加载可见图 |
| 首屏例外 | 折叠以上第一屏用 `loading="eager" fetchpriority="high"` | 避免 LCP 图片被 lazy 拖累 |
| 显式尺寸 | `width/height` 或 `aspect-ratio` | 消除 CLS（累计布局偏移） |
| 响应式尺寸 | `<Picture>` + `widths={[320,480,720]}` + `sizes` | 手机不下载大图 |
| 缩略图分离 | 列表用构建期生成的 480w 缩略图，灯箱才用原图 | 灯箱按需加载，不预载全部原图 |
| 渐进解码 | `decoding="async"` | 不阻塞主线程 |

> 参考站这几项**一个都没做**（实测：封面 `<img>` 无 `loading`、无 `srcset`，首屏 6 张外站图全量并发加载）——这是它的明显短板，我们不要继承。

### 4.4 灯箱联动

- 复用 `blog/[slug].astro` 里已写好的 Lightbox（遮罩挂 body、ESC/遮罩/按钮关闭、方向键、触摸滑动、计数）
- 改造点：支持传入"图片数组 + 起始索引"，网格中点第 5 张 → 灯箱从第 5 张开始，可左右切换
- ⚠️ 注意：文章页曾踩过 **`backdrop-filter` 劫持后代 fixed 定位**的坑（目录飞出屏幕）。网格卡片在毛玻璃面板内，灯箱遮罩**必须挂在 body**，不能放进面板

### 4.5 与现有资产的复用清单

| 复用 | 说明 |
| --- | --- |
| `--card` / `--border` / `--accent` | 毛玻璃卡片与强调色 |
| `--dur-fast/base/slow` / `--ease` | 今天刚统一的动效节奏 |
| `.reveal` 进场模式 | 首页同款逐条错开 |
| Lightbox 组件逻辑 | 从文章页抽出复用 |
| 目录粘性模式 | 右侧筛选栏可沿用 `position: sticky` + grid item 方案 |

## 6. 风险与规避清单

| # | 风险 | 后果 | 规避手段 |
| --- | --- | --- | --- |
| 1 | 图片无尺寸信息 | CLS 抖动，SEO 扣分 | `width/height` 或 `aspect-ratio` 必填 |
| 2 | 首屏一次加载几十张 | 首屏白屏几秒 | lazy + 首屏 eager 例外 + 分批渲染（`content-visibility: auto`） |
| 3 | **EXIF 隐私** | 手机照片的 GPS/机型/时间被公开 | 入库前用 `exiftool`/脚本清洗元数据。**照片类站点最常被忽略的风险** |
| 4 | 灯箱原图过大 | 点开卡顿、移动端内存飙升 | 灯箱图限宽 2000px，生成 webp 副本 |
| 5 | `.glass-panel` 的 backdrop-filter 劫持 fixed | 灯箱/弹层飞出屏幕 | 遮罩挂 `body`，不放面板内（已踩过） |
| 6 | 移动端无 hover | 放大效果失效，体验断层 | `<640px` 直接点击开灯箱，不依赖 hover |
| 7 | 外链图失效 / 版权 | 图挂全站崩 | 全部本地化，不用图床 API |
| 8 | `prefers-reduced-motion` 遗漏 | 前庭敏感用户不适 | 所有动效在 reduce 下关闭 |
| 9 | 图片 alt 缺失 | 无障碍与 SEO 双失 | alt 取 title，装饰性图 `alt=""` |
| 10 | 图片版权（他人作品） | 纠纷 | 只放自己拍的/自己画的，转载注明来源 |
| 11 | 网格图片比例不一 | 排版参差 | 统一裁切比例（列表 3:2 / 移动 4:3），`object-fit: cover` |
| 12 | 未来图片过多 | 页面变长、构建变慢 | 预留分页或按年份分组；超 100 张时改"分组 + 懒加载" |
