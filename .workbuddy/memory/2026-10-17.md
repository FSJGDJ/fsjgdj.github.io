## 文章侧边目录（TOC）折叠交互

需求：一级标题（h2）下的子条目（h3）默认收起，正文滚动到该章节时展开，其余收起。只做这一个交互，最小改动。

**定位结论**
- 目录渲染全在 `src/pages/blog/[slug].astro`：移动端 `<details class="toc toc-mobile">`（约 66–79 行）+ 桌面端 `<aside class="toc toc-desktop">`（经 `slot="toc"` 渲染到 glass-panel 之外，约 114–127 行）。
- 数据**构建时**生成：`render(post)` 的 `headings` 过滤 depth 2/3，原先是扁平 `<ol>`（depth-3 仅靠 `padding-left` 缩进）。
- active 判定：同文件 IIFE 里基于滚动位置——「参考线 `HEADER_OFFSET=96px` 之上最后一个标题」，近底部锁定最后一个。

**实现（只改这一个文件，+194/-10）**
- frontmatter 新增 `tocTree`：把扁平 toc 归并成「一级章节 → 子条目」两层，孤儿 depth-3 自成一级章节。
- 两份目录模板改渲染嵌套结构，一级 `<a>` 加 `aria-expanded="false"`，子级 `<ol class="toc-sub">` 带 `aria-hidden="true" inert`。
- 折叠状态**以 `aria-expanded` 为唯一事实来源**（CSS 直接按它选 `max-height`），脚本只改这一个属性。
- 脚本在原 IIFE 内追加：`sections` 按 hash 归并移动/桌面两份目录 → `setSectionOpen`（切换时实测 `scrollHeight` 写入 `--toc-sub-h`，并同步 aria-hidden/inert）→ `currentSection`（只看 depth-2 元素位置，顶部回退到第一节）→ `syncSections`（挂到 `computeActive()` 末尾）→ `keepActiveVisible`（只改 `.toc-desktop` 的 scrollTop，不碰 window，避免连带滚动整页）。
- 初始化：临时把子级 `transition` 设为 none 避免首帧闪烁，rAF 恢复；带 hash 时先按 hash 所属章节展开一次，随后第一次 scroll 按实际位置接管。
- CSS 只新增 3 条规则（`.toc ol.toc-sub`、`[aria-expanded="true"] + ol.toc-sub`、reduce 下 `transition:none`），并给嵌套 ol 加 `border-left:none` + `margin-left:-2px`，保证竖线不重复、子条目文字起始位置与改动前**完全一致**。

**踩坑**
1. 最初用 `grid-template-rows: 0fr → 1fr`，实测在高度不定的 grid 容器里**根本收不起来**（`0fr` 被解析成 max-content，多子项时只有第一行归零）。改用 `max-height: 0 → 实测 scrollHeight px`。独立测试页已验证两者差异。
2. 过渡时长用 `--dur-slow`（0.3s）而非 `--dur-base`：281px 高的子列表用 200ms 偏急。
3. Playwright 探针踩了三个坑（采样落在过渡起点、断言引用不存在的字段、期望值没考虑"当前章节无子级"），一度误报 3 个 FAIL——实际代码是对的。

**验收**：写了 30 项自动化检查（playwright-core + 本机 Chrome），全部通过——41 采样点滚动中始终恰好一个展开且与一级标题位置一致、快速滚动/顶部/底部边界、hash 直达与刷新、点击收起的一级标题、展开态点子条目跳转、`inert` 键盘拦截、reduced-motion 关闭过渡、窄屏、无 h3 文章不回归、控制台无报错。脚本保留在 `.workbuddy/binaries/node/workspace/toc-verify.mjs` 便于复用。
